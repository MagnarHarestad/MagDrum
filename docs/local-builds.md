The Windows x64 app, VST3, tests, and Cubase ZIP can be built without a GitHub Actions runner:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows.ps1
```

Windows ARM64 is outside the current x64/Cubase target. If the user later requests an ARM64 build, use this command:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows.ps1 -Architecture ARM64
```

The script reuses the persistent `build/local-windows-release` directory by default, builds the app and VST3, runs CTest, assembles the standalone app, plugin bundle and installer, and writes the ZIP to `latest-publish/MagDrum-Windows-x64.zip`. Keep this tree for future Windows x64 test releases; a new build directory triggers a full JUCE rebuild. Although the directory name records when this tree was created, it is intentionally fixed and will not change on a new day or release number. The script updates JUCE's generated Windows resource files only when their version is stale, so an unchanged version does not force an app/plugin relink on every run. After packaging, it verifies required installers and license notices, the app/plugin version numbers, and the Microsoft runtime signature. Configure, compile/link, tests and packaging durations are printed so slow stages are visible. With `-Architecture ARM64` it uses a separate build directory and writes `MagDrum-Windows-ARM64.zip`; ARM64 tests are cross-compiled but CTest is skipped because the x64 host cannot execute those binaries. Run them on native ARM64 Windows. If the default CMake build folder is locked or damaged, pass a fresh repository-relative path, for example `-BuildDirectory build/local-windows-x64-clean`. The script prints the SHA-256 for release notes. It does not create a GitHub release. After reviewing the packages, use `Publish-LocalRelease.ps1` with an explicit test tag and asset list; it uploads directly to GitHub Releases without starting Actions.

The first build compiles JUCE and takes several minutes. Later runs reuse the CMake build. For everyday edits, `Build-Windows-Plugin.ps1` reuses `build/local-windows-dev-x64` and skips tests, packaging, publishing and installation; its fixed path remains the default across days. Batch related changes, then run the full Release script once for the Cubase-ready milestone. Keep one build at a time per tree. Requirements are CMake, Git, Visual Studio's C++ desktop workload, and a Windows x64 host. ARM64 cross-compilation additionally requires Visual Studio's ARM64 C++ tools. `-SkipTests` configures CMake without the test targets and omits CTest; use it only for a local iteration package, then run the default full build before publishing.

The iOS library UI and the AUv3 editor layout (without the desktop VST3 scanner) can be compile-checked on Windows with desktop preview targets. This does not produce an iOS app or verify Apple entitlements:

```powershell
cmake -S . -B build/local-windows-x64-mobile-preview -A x64 `
  -DBUILD_TESTING=ON -DMAGDRUM_BUILD_MOBILE_PREVIEW=ON
cmake --build build/local-windows-x64-mobile-preview --config Release --target MagDrumMobilePreview MagDrumPlugin_VST3 MagDrumPluginTests
ctest --test-dir build/local-windows-x64-mobile-preview -C Release --output-on-failure
```

On a native Linux or macOS host, use the matching local script:

```sh
bash ./Build-Unix.sh
```

On macOS this builds the host architecture by default. An Apple Silicon Mac with Xcode can also configure an Intel build using `bash ./Build-Unix.sh x86_64`; use `bash ./Build-Unix.sh arm64` for an Apple Silicon build. Each archive is written to `latest-publish`. macOS packages include the app, VST3, and AU bundles. Linux packages include the app and VST3. The script runs CTest before packaging and prints the archive SHA-256.

On Ubuntu, run `bash tools/Install-LinuxBuildDependencies.sh` to install the compiler, CMake, Git, and JUCE's ALSA, JACK, LADSPA, FreeType, Fontconfig, X11, EGL and Mesa GLU development packages. The WebKitGTK and curl packages are not needed because this project's JUCE targets compile with `JUCE_WEB_BROWSER=0` and `JUCE_USE_CURL=0`. Then build with `bash ./Build-Unix.sh`. For faster builds, clone the repo inside the WSL Linux filesystem (for example `~/src/MagDrum`) rather than building under `/mnt/c`; the script writes its package to the clone's `latest-publish` directory. Copy `MagDrum-Linux-x64.tar.gz` from that directory into the Windows checkout's `latest-publish` folder before running `Publish-LocalRelease.ps1`. A WSL archive still needs a smoke test on a supported native Linux host before it is treated as fully verified.
