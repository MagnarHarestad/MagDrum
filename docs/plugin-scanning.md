# Scanning sounds from an instrument plugin

The desktop app can discover installed audio plugins using JUCE's plugin list. Use the list's options to scan default locations or add a custom folder. MagDrum keeps the discovered plugin inventory in its local SQLite database and caches JUCE's plugin descriptions in the user's application data folder. With a loaded VST3 instrument, choose **Find VST3 presets** to recursively search a user-selected folder for `.vstpreset` files. Select a result to ask that instrument to load it. MagDrum does not copy preset files; the plugin validates whether a preset belongs to it. After a successful load, enter or keep a kit name and use **Save state** if you want to recall that kit from MagDrum later.

## Capture a kit

1. Select an instrument plugin and load it. MagDrum opens the plugin's own editor. In the sample browser, select a captured preview and use **Open source kit** to load the same instrument and recall its saved kit state. The instrument must still be installed and discoverable.
2. Choose a kit or preset in that editor. MagDrum does not assume that the plugin exposes a list of presets.
3. Close the editor, enter a kit name, and save the current plugin state. The state can later be recalled by loading the same instrument and choosing that kit name.
4. Choose velocity levels, note duration, release time, total capture length and repeat count (1–8), then start the scan. MagDrum sends MIDI notes 0–127 at each selected velocity and renders each repeat offline.
5. MagDrum records silent notes, analyzes audible output, writes a WAV preview for each audible take under its application data directory and indexes the previews in the sample browser. Repeated takes appear with their take number. The original plugin state is restored after the render.
6. After a scan, use **View layer candidates** with the same kit name to review large acoustic-fingerprint changes between adjacent sampled velocities. Use **View round-robin candidates** to review notes where repeated triggers produced distinct fingerprints. Both reports are heuristic listening aids; variation does not prove an instrument implements round-robin playback or reveal its internal sample-layer boundaries. Listen to the take WAVs in the sample browser.

The scan runs in a separate MagDrum worker process, away from both the real-time audio callback and the main app process. If a third-party plugin crashes or hangs, MagDrum can report the worker failure and remain open; a worker that does not stop after cancellation is terminated after a short grace period. Cancellation takes effect between captures; partial scans replace the saved candidate set with the captures completed so far. Some plugins may not render correctly offline or may not provide serializable state. Preview WAVs stay local and are not part of MagDrum's release packages. Increasing repeats, velocities or capture length increases memory use; scans over the 512 MiB safety limit are rejected. A real third-party plugin crash/recovery fixture is not yet part of the automated checks.
