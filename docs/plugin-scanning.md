# Scanning sounds from an instrument plugin

The desktop app can discover installed audio plugins using JUCE's plugin list. Use the list's options to scan default locations or add a custom folder. MagDrum keeps the discovered plugin inventory in its local SQLite database and caches JUCE's plugin descriptions in the user's application data folder. With a loaded VST3 instrument, choose **Find standard presets** to search the platform's standard `.vstpreset` folders for that vendor and instrument. Search follows the VST3 priority order: current-user presets, shared presets, then presets shipped with the running application. Choose **Choose preset folder** to search another folder recursively. Select a result to ask that instrument to load it. MagDrum does not copy preset files; the plugin validates whether a preset belongs to it. After a successful load, enter or keep a kit name and use **Save state** if you want to recall that kit from MagDrum later. Standard locations follow the [VST3 Developer Portal preset-location specification](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical%2BDocumentation/Locations%2BFormat/Preset%2BLocations.html).

## Capture a kit

1. Select an instrument plugin and load it. MagDrum opens the plugin's own editor. In the sample browser, select a captured preview and use **Open source kit** to load the same instrument and recall its saved kit state. The instrument must still be installed and discoverable.
2. Choose a kit or preset in that editor. MagDrum does not assume that the plugin exposes a list of presets.
3. Close the editor, enter a kit name, and save the current plugin state. The state can later be recalled by loading the same instrument and choosing that kit name.
4. Choose velocity levels, note duration, release time, total capture length and repeat count (1–8), then choose a render mode. **Offline (fast)** is the default. If the instrument does not behave correctly while marked non-realtime, try **Real-time paced**; MagDrum sends blocks at the audio sample-rate pace and marks the plugin as realtime. **Audio device fallback** opens the system's default output and runs the plugin from its real device callback. The callback's captured sample rate is stored with the resulting previews. This mode can send the instrument's sound to the selected physical outputs.
5. MagDrum records silent notes and writes each completed capture and its metadata to a recoverable worker log immediately. Audible takes are analyzed and indexed as previews under the application's data directory. Repeated takes appear with their take number. The original plugin state is restored after the render.
6. After a scan, use **View layer candidates** with the same kit name to review acoustic-fingerprint changes between adjacent sampled velocities. The dialog lets you record manually confirmed ranges as `note:min-max` entries, separated by semicolons, for example `36:1-48; 36:49-127`. Ranges for one note may not overlap. Use **View round-robin candidates** to review repeated-trigger variations, listen to the take WAVs in the sample browser, then select a reviewed candidate and choose **Toggle confirmation**. This saves the exact audible take indices as a user-confirmed group; selecting it again removes that confirmation. Heuristic candidates remain separate from user confirmations, and neither one proves the plugin's internal implementation.

The scan runs in a separate MagDrum worker process, away from the main app process. Every completed capture is saved to disk before the next one begins. If a worker crashes or is stopped after it hangs during cancellation, MagDrum recovers the completed captures and indexes them while keeping the main app open. Tests cover a worker abort after a capture and verify recovery of its record; a real third-party VST3 crash fixture is still needed. Cancellation takes effect between captures; partial scans keep the captures completed so far. Streaming keeps only one audio capture in memory at a time. Real-time paced mode follows wall-clock sample timing but does not open or route through an audio device. Audio device fallback uses the system default output callback, but it has not yet been validated against commercial plugins or device drivers. Some plugins may not render correctly offline or may not provide serializable state. Preview WAVs stay local and are not part of MagDrum's release packages.
