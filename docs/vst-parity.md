# Standalone-to-VST functionality parity

The VST is intended to expose the MagDrum workflows from inside Cubase. This checklist tracks parity without claiming that the standalone app and an instrument plug-in have identical host responsibilities.

| Standalone workflow | VST status | VST implementation target |
| --- | --- | --- |
| Recursive sample-folder scan, file analysis, cancellation, resume, scan history | Implemented on Windows x64 | The VST scans in a background worker, shares the same database, reports progress and scan results, exposes scan history, and can scan detected default Native Instruments, Spectrasonics/STEAM and Steinberg/Cubase locations. WAV/AIFF/FLAC audio is indexed; proprietary VST Sound archives are not unpacked. |
| Find and import drum MIDI patterns from installed default libraries | Implemented on Windows x64 | The default-library scan searches the detected folders for drum-related `.mid`/`.midi` files. The sequencer lists the first 200 results and imports the selected pattern using the active mapping profile. Focused fixtures cover extension case, relevance filtering, result limits and cancellation. |
| Sample search, category/source/kit filters, feature bands, confidence review and sorting | Implemented | The VST exposes the standalone browser filters, sort options and paged results. |
| Sample audition, waveform, category/tag edits, source-kit access, sample comparison | Partial | Preview, category and tag editing, and two-file waveform comparison are in the VST. Source-kit access remains. |
| Exact and perceptual duplicate lookup, similarity candidates | Implemented | The Sample tools menu reports exact duplicates, acoustic-similarity and perceptual near-duplicate candidates. |
| Plugin-instrument discovery, presets, saved states, MIDI-note/velocity scans, round-robin and layer review | Not ported | Provide an in-plugin scan workspace using isolated workers. Use host-driven rendering where an independent audio device is unavailable. |
| Semantic MIDI import/export, event editor, ambiguity/fallback reports, GM/custom profiles and CSV profile import/export | Partial | The VST imports and exports 16-bar patterns, reports ambiguous/unmapped/out-of-range notes, and edits saved GM/custom CSV profiles. The selected profile, up-to-512-step pattern, tempo and opening time signature are stored in Cubase plug-in state. A full event/metadata editor remains. |
| Multi-bar, meter-aware sequencer, editable velocity, tempo/signature metadata, preview and loop | Partial | The VST has sixteen selectable bars in a chosen supported meter, per-step velocity presets, tempo and looping sample preview. Time-signature changes later in a pattern and later tempo events remain unsupported. |
| Portable metadata archive import/export | Implemented | The Sample tools menu imports and exports the shared tag/category/mapping-profile archive without copying audio. |

The VST cannot take ownership of Cubase's audio device. Any standalone action that currently opens or configures a device must use the DAW's playback/render callbacks or a separate worker instead. Windows x64 is the first target for parity work; other plug-in formats must be rebuilt and reviewed after the Windows behavior settles. Instrument scanning/preset rendering, source-kit controls, full MIDI metadata editing, and tempo or meter event editing later in the pattern remain parity gaps.
