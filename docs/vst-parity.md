# Standalone-to-VST functionality parity

The VST is intended to expose the MagDrum workflows from inside Cubase. This checklist tracks parity without claiming that the standalone app and an instrument plug-in have identical host responsibilities.

| Standalone workflow | VST status | VST implementation target |
| --- | --- | --- |
| Recursive sample-folder scan, file analysis, cancellation, resume, scan history | Implemented on Windows x64 | The VST scans in a background worker, shares the same database, reports progress and scan results, exposes scan history, and can scan detected default Native Instruments, Spectrasonics/STEAM and Steinberg/Cubase locations. WAV/AIFF/FLAC audio is indexed; proprietary VST Sound archives are not unpacked. |
| Find and import drum MIDI patterns from installed default libraries | Implemented on Windows x64 | The default-library scan searches the detected folders for drum-related `.mid`/`.midi` files. The sequencer lists the first 200 results and imports the selected pattern using the active mapping profile. Focused fixtures cover extension case, relevance filtering, result limits and cancellation. |
| Sample search, category/source/kit filters, feature bands, confidence review and sorting | Implemented | The VST exposes the standalone browser filters, sort options and paged results. |
| Sample audition, waveform, category/tag edits, source-kit access, sample comparison | Partial on Windows | Preview, category and tag editing, two-file waveform comparison, and captured-sample source/kit/MIDI metadata are in the VST. The VST can launch a separate MagDrum helper with the selected sample's source instrument and saved kit; that helper reopens the instrument editor. |
| Exact and perceptual duplicate lookup, similarity candidates | Implemented | The Sample tools menu reports exact duplicates, acoustic-similarity and perceptual near-duplicate candidates. |
| Plugin-instrument discovery, presets, saved states, MIDI-note/velocity scans, round-robin and layer review | Partial on Windows x64 | The VST's Plugin Scanner can discover standard VST3 locations and import a chosen `.vstpreset` in an isolated MagDrum helper, then save its state as a named kit in the shared database. It selects a saved kit, configures note/velocity capture and scans it in an isolated worker. Captures and layer/round-robin analyses are shared with the VST library. Interacting with a plugin-specific editor or selecting programs not stored as `.vstpreset` files still uses the separate instrument manager. |
| Semantic MIDI import/export, event editor, ambiguity/fallback reports, GM/custom profiles and CSV profile import/export | Partial | The VST imports patterns with lengths inferred from MIDI files and exports patterns with selectable lengths from 1–16 bars, reports ambiguous/unmapped/out-of-range notes, edits saved GM/custom CSV profiles, and lets users add/remove tempo and time-signature events at any quarter-note beat. The sequencer can edit individual hit drum, articulation, velocity, beat position and duration, then compare the imported baseline with current edits (added/removed hits, metadata and pattern length). The event list is preserved in Cubase plug-in state and MIDI export; grid edits update only the corresponding hit so off-grid events elsewhere remain intact. |
| Multi-bar, meter-aware sequencer, editable velocity, tempo/signature metadata, preview and loop | Partial | The VST has sixteen selectable bars in a chosen supported meter, per-step velocity presets, editable tempo and meter events, and looping sample preview. Tempo events affect preview playback. Later meter events are retained on MIDI export, while the step grid continues to use the opening meter. |
| Portable metadata archive import/export | Implemented | The Sample tools menu imports and exports the shared tag/category/mapping-profile archive without copying audio. |

The VST cannot take ownership of Cubase's audio device. Any standalone action that currently opens or configures a device must use the DAW's playback/render callbacks or a separate worker instead. Discovery, preset loading and note scanning use separate MagDrum helpers, so third-party plugins are not loaded into Cubase by these workflows. Windows x64 is the first target for parity work; other plug-in formats must be rebuilt and reviewed after the Windows behavior settles. Plugin-specific editors and non-preset program selection remain in a separate MagDrum manager process.
