# Standalone-to-VST functionality parity

The VST is intended to expose the MagDrum workflows from inside Cubase. This checklist tracks parity without claiming that the standalone app and an instrument plug-in have identical host responsibilities.

| Standalone workflow | VST status | VST implementation target |
| --- | --- | --- |
| Recursive sample-folder scan, file analysis, cancellation, resume, scan history | Implemented on Windows x64 | The VST scans in a background worker, shares the same database, reports progress and scan results, exposes scan history, and can scan detected default Native Instruments (including the shared Public Documents content root), Spectrasonics/STEAM and Steinberg/Cubase 15 VST Sound and Media locations. WAV/AIFF/FLAC audio is indexed; proprietary VST Sound archives are not unpacked. |
| Find and import drum MIDI patterns from installed default libraries | Implemented on Windows x64 | The default-library scan searches the detected folders for drum-related `.mid`/`.midi` files. The sequencer lists the first 200 results and imports the selected pattern using the active mapping profile. Focused fixtures cover extension case, relevance filtering, result limits and cancellation. |
| Sample search, category/source/kit filters, feature bands, confidence review and sorting | Implemented | The VST exposes the standalone browser filters, sort options and paged results. SQLite queries are debounced and run on a background worker so large-library filtering does not block the editor. |
| Sample audition, waveform, category/tag edits, source-kit access, sample comparison | Partial on Windows | Preview, category and tag editing, two-file waveform comparison, and captured-sample source/kit/MIDI metadata are in the VST. The VST can launch a separate MagDrum helper with the selected sample's source instrument and saved kit; that helper reopens the instrument editor. |
| Exact and perceptual duplicate lookup, similarity candidates | Implemented | The Sample tools menu reports exact duplicates, acoustic-similarity and perceptual near-duplicate candidates. |
| Plugin-instrument discovery, presets, saved states, MIDI-note/velocity scans, round-robin and layer review | Partial on Windows x64 | The VST's Plugin Scanner discovers standard VST3 locations and can add a user-selected plugin folder to the scan, enumerate programs exposed by an instrument, and import a chosen `.vstpreset` in an isolated MagDrum helper. It can save either a selected program or preset as a named kit in the shared database, select that kit, configure note/velocity capture and scan it in an isolated worker. Captured samples are searchable in the VST; its Sample tools now show layer/round-robin candidates and save user-confirmed velocity ranges and take groups. Interacting with a plugin-specific editor still uses the separate instrument manager. Manual Cubase review remains pending. |
| Semantic MIDI import/export, event editor, ambiguity/fallback reports, GM/custom profiles and CSV profile import/export | Partial | The VST imports patterns with lengths inferred from MIDI files and exports patterns with selectable lengths from 1–16 bars, reports ambiguous/unmapped/out-of-range notes, edits saved GM/custom CSV profiles, and lets users add/remove tempo and time-signature events at any quarter-note beat. The sequencer can edit individual hit drum, articulation, velocity, beat position and duration, then compare the imported baseline with current edits (added/removed hits, metadata and pattern length). The event list is preserved in Cubase plug-in state and MIDI export; grid edits remove only hits on the selected 1/8, 1/16 or 1/32 grid and preserve off-grid hits with a status message directing the user to Edit hits. Sequencer playback now maps each semantic event through the selected profile without fallback; missing exact mappings are skipped and reported. |
| Multi-bar, meter-aware sequencer, editable velocity, tempo/signature metadata, preview and loop | Partial | The VST has sixteen selectable bars, 1/8, 1/16 and 1/32 step grids (up to 32 steps per bar), variable meter changes aligned to the selected grid, per-step velocity presets, editable tempo and meter events, and looping sample preview. When the DAW is stopped, Play uses the plugin's tempo-aware preview. During host playback, the audio callback schedules semantic hits against the host's PPQ position and BPM at sample offsets and wraps at the pattern length; the host tempo is authoritative for this mode. The grid maps later time signatures into shorter or longer bar spans and MIDI export retains them. Core tests cover block boundaries, loop wrap, tempo-to-sample timing, and negative-position preroll. Manual Cubase Pro 15 transport and audio review remains pending. |
| Portable metadata archive import/export and folder sync | Implemented on Windows x64 | The Sample tools menu imports/exports version 1 archives and syncs version 2 device snapshots through a user-selected folder. Folder sync carries tag additions and removals, manual categories and MIDI profiles; add/remove operations match local samples by content hash and size. It never copies audio or local paths. Shared-core tests cover removal propagation and concurrent re-adds; Cubase UI validation remains pending. |

The VST cannot take ownership of Cubase's audio device. Any standalone action that currently opens or configures a device must use the DAW's playback/render callbacks or a separate worker instead. Discovery, program enumeration, preset/program loading and note scanning use separate MagDrum helpers, so third-party plugins are not loaded into Cubase by these workflows. Windows x64 is the first target for parity work; other plug-in formats must be rebuilt and reviewed after the Windows behavior settles. Plugin-specific editors remain in a separate MagDrum manager process.

## Windows development and installation loop

Work Windows x64 only until the Cubase Pro 15 experience is accepted. Do not spend iteration time on Linux or macOS packages unless requested.

For each focused code or UI change, use `Build-Windows-Plugin.ps1`. Its separate x64 Debug tree builds only the standalone scanner helper and VST3 in one MSBuild invocation, without Release link-time optimization. It also skips tests, packaging and installation. The script reuses `build/local-windows-dev-x64` and prints the elapsed time; keep using that tree so MSBuild can reuse compiled JUCE and MagDrum objects. A previous warmed UI edit took about 14 seconds in this tree; a recent warmed layout edit completed in about 3 seconds. Those are incremental-edit timings, not clean-build estimates. Open that Debug bundle in Cubase only when host review is useful; do not create a numbered release for each edit.

Batch related changes into a usable feature milestone. Then run `Build-Windows.ps1 -BuildRevision <test-number>` once: it checks localization and installer safeguards, builds the optimized Release app and VST3, runs the Windows x64 tests, and produces the ZIP. Set the revision to the release tag and adjust `-Parallel` only when the machine is responsive. `-SkipTests` is for a local package when test executables are not needed; it is not the release check. The publisher rejects a Windows archive whose VST3 version does not match its test tag. The installer preserves the replaced MagDrum bundle in backup and moves other MagDrum bundles out of JUCE's two standard scan roots; it leaves other vendors' plugins untouched.

Keep the next work tied to Cubase acceptance: first verify sample discovery, assignment and MIDI playback inside the VST; then close remaining sequencer, saved-state and scanner issues found in host use; finally package and release a Windows x64 milestone for hands-on review. Pause work on ancillary research and non-Windows packaging while a Windows workflow blocker remains. When Cubase review is available, test the Release package after publishing so validation exercises the same binary users download. Linux and macOS builds remain deferred until requested.
