# MagDrum Windows plug-in views

The Windows VST3 editor is organized into five views. Open MagDrum on an instrument track in Cubase and choose a view from the navigation row. The **Plugin Scanner** view can discover VST3 instruments, list exposed programs, import presets as kits, and run note capture from inside the VST. The separate instrument manager remains useful for plugin-specific editors.

## Sample Library

VST sample previews are decoded on a cancellable background worker, so large files do not block Cubase's editor thread. If you request another preview while one is loading, the older request is cancelled and the newer selection takes priority.

The sample map projects the indexed four-window, 16-band acoustic fingerprints onto two principal components so samples with similar spectra tend to appear near one another. Projection runs in a background worker. Libraries with more than 3,000 loaded samples show an even representative subset in the map while the full result list remains available. Points keep their drum-category colors. Hover to inspect a sample and click to select it; double-click a point to audition, and move the pointer away to stop that preview. Scroll the mouse wheel to zoom around the pointer and drag with the middle button to pan; points and their glow remain clipped to the map. Double-click a sample row to audition it. Right-click a row for Preview, Assign to pad, source-kit access when available, and Sample tools. Older samples without a usable fingerprint are placed using their duration and brightness instead.

Keep the main views focused by showing only frequent actions. Before adding a button, look for a clearer interaction that fits the content: a contextual action, double-click, keyboard shortcut, inline control, slider for a continuous value, or searchable/filterable list for many choices. Combine related actions when their relationship is clear, and reveal advanced options only when they are relevant. Avoid hiding navigation, essential state, or important actions behind unexplained gestures; provide visible cues or tooltips. Keep file selection and follow-up forms inside the plug-in view so the workflow stays in MagDrum.

While a sample preview is active, click **Stop** to cancel a file decode or silence playback. The comparison view also has a **Stop** action below each waveform.

To audition a pair while comparing them, Ctrl-click exactly two sample rows and choose **Sample tools > Compare two selected waveforms**. The comparison opens inside the plug-in. Use the **Preview** action under either waveform to hear that sample through the instrument output; choosing the other replaces the active comparison preview. File and folder selection for plug-in actions also stays inside the current MagDrum view, with **Back** returning to the view you came from.

In **Plugin Scanner**, **Scan plugin folders...** opens one menu for scanning standard VST3 locations, choosing an additional folder, or refreshing the saved instrument list. The same button becomes **Cancel instrument scan** while discovery runs in the separate MagDrum helper, outside Cubase.

Select a discovered instrument, then open **Choose kit source...** to select a `.vstpreset` file, search that instrument's standard VST3 preset locations, search a chosen folder, or scan its exposed programs. Preset searches run in the background; the source button becomes **Cancel** while a search is active. Matching preset files appear in an in-app menu, and choosing one fills the kit name and enables **Import preset as kit**. The instrument validates the selected preset during isolated import.

In **MIDI Maps**, selecting a profile loads it immediately. Use **Save profile** to store the current name and mapping; **Import CSV...** groups CSV import and export, and **Set mapping...** groups mapping creation and removal for the selected drum and articulation.

Library rows also show which MIDI notes and velocity ranges currently use each sample. This updates after pad assignment, clearing a pad, and project-state restoration.

On Windows, Native Access places its default content location at `C:\Users\Public\Documents`. MagDrum scans this shared root as well as detected vendor locations, so libraries installed directly beneath it are included. Nested known vendor folders are collapsed under the root to avoid scanning the same files twice.

Click **Scan samples** in the Sample Library to choose **Scan installed libraries**, **Add sample folder**, or resume an interrupted scan. Installed-library scanning covers detected default Native Instruments, Spectrasonics/STEAM and Steinberg/Cubase 15 VST Sound and Media folders, including Steinberg per-user content under Roaming AppData. The scan runs in the background across the folders it finds, can be cancelled during audio indexing and the follow-up drum-MIDI search, skips unchanged files, saves checkpoints, and resumes interrupted audio scans. It also searches those folders for drum-related `.mid` and `.midi` files; open **Drum MIDI (N)** in the sequencer to inspect and import a result. The audio index reads supported WAV, AIFF and FLAC files. The scan reports Steinberg `.vstsound` containers and Kontakt `.ncw` samples that it cannot read directly, then guides you to Plugin Scanner to capture audio from the installed instrument. The resulting sample index is shared with the MagDrum desktop app. VST sample searches and filter updates are debounced and run in the background, keeping the editor responsive with large libraries. Opening **Plugin Scanner** refreshes the saved instrument list and starts discovery automatically if it is empty. Use **Scan plugin folders** to refresh discovery in the standard locations. Discovery runs in a separate MagDrum process so third-party plugins are not loaded inside Cubase. Select an instrument and use **Choose kit source** to choose a `.vstpreset` file, search standard preset locations, search a chosen folder, or scan exposed programs. Preset search results appear in an in-app menu; selecting one sets the kit name before import. Enter a kit name, select either a program or a preset, then use the single import button (its label reflects the selected source). The kit scan button becomes **Cancel scan** while the background scan is running. The helper loads the selected sound outside Cubase and saves its plugin state in the shared database. Select the saved kit, configure velocity levels and capture timing, then click **Scan kit notes**. That note scan also runs in a separate helper process; its captures and analysis appear in this VST's library. Select one of those captured samples and use **Sample tools > View layer candidates** or **View round-robin candidates** to review the analysis and save confirmed velocity ranges or take groups. The separate **Plugin instruments** manager remains available for instrument-specific editor interaction. Captured instrument samples show their source plugin, kit, MIDI note, velocity, articulation and take in the browser. Search by text/tags or filter by category, source, kit, duration, brightness and review confidence. The next page loads automatically as you scroll near the end of a large result list, and the status line signals when more results are available. The list shows category, duration and measured brightness; the map projects stored acoustic fingerprints onto two principal components so sounds with similar spectra tend to appear near each other, with dots colored by category. Samples without a fingerprint use duration and brightness for an estimated position. Hover a point for its filename, category, duration and brightness; click it to select the sample. Click a point or list row to select a sound, then use **Preview** (or double-click a list row) to audition it. Select a pad in **Drum Machine** first, return to the library, and choose **Assign to pad** to load the selected sample on that MIDI note. **Sample tools** also provides category and tag editing, scan history, similarity and duplicate searches, waveform comparison, and portable metadata import/export.

## Drum Machine

The 4×4 pad grid follows the Boss DR-660 layout: crashes and ride sounds on the top row, toms next, side stick/clap/hi-hats on the third row, then Kick, Snare, Pedal HH and Cowbell along the bottom. The Windows x64 build uses Cubase's octave convention for pitch labels: bottom-left Kick is C1 (MIDI note 36), Snare is D1 (38), Closed HH is F#1 (42), Open HH is A#1 (46), Pedal HH is G#1 (44) and Cowbell is G#2 (56). Pads glow briefly when triggered. Click a pad to select it and audition its assigned sound. The panel beside the grid shows the sample waveform, file path and assigned velocity layers. **Load sample** loads a local audio file directly; **Layers > Clear pad** removes all layers from that note, while the same menu also provides per-layer preview, velocity-range editing and removal. To assign a library sample, select the pad first, then return to **Sample Library** and use **Assign to pad**. Velocity ranges are inclusive, from 1 to 127, and may not overlap. The selected MIDI note has independent Gain, Pan and Tune controls plus an ADSR envelope (Attack, Decay, Sustain and Release) and a resonant low-pass filter with Cutoff and Q controls. Q ranges from 0.5 to 10; the maximum Cutoff setting bypasses the filter. These values are applied during sample playback, saved in the Cubase project and restored with the pad.

## Sequencer

Choose a pattern length from 1 to 16 bars; the bar selector only shows bars within that length. The grid has 16 named lanes in this order: Kick (36), Snare (38), Closed hi-hat (42), Open hi-hat (46), Tom 4 (43), Ride (51), Crash 1 (49), Clap (39), Bell (53), Crash 2 (57), Tom 1 (50), Tom 2 (47), Tom 3 (45), Side Stick (37), Pedal hi-hat (44) and Cowbell (56). Notes shown here are the General MIDI defaults; the active MIDI profile can change the first nine lane mappings. The remaining lanes retain their dedicated notes so secondary crashes, toms, Bell, Side Stick, Pedal hi-hat and Cowbell stay independently playable. Choose a 1/8, 1/16 or 1/32 grid, with up to 32 steps per bar. Right-click a step to set its velocity. Choose a time signature from the meter menu; the grid supports up to 32 steps per bar at the selected resolution and keeps its lane mappings. Set tempo from 20 to 300 BPM. Use **Set event** and **Remove event** to edit tempo or time-signature metadata at any quarter-note beat; the event summary shows the metadata that will be exported. Tempo events also change the sequencer preview tempo. Time-signature changes on selected grid boundaries create the corresponding shorter or longer bar spans in the grid and remain in the exported MIDI. **Play** loops the selected pattern length through assigned samples. The **MIDI** menu groups import, discovered **Drum MIDI (N)** patterns, export, hit editing, change review and clearing the pattern. Imports use the selected profile and report unmapped, ambiguous and out-of-range notes. MIDI import selects a pattern length from the file duration, up to 16 bars. Length, meter, pattern steps and metadata are saved with Cubase plug-in state; shortening the pattern is rejected if it would hide existing hits. Export writes only the selected pattern length, including step velocities and all stored tempo/time-signature events. Steps with no sample assigned remain silent during preview and will play if Cubase receives MIDI for a loaded note.

## MIDI Maps

Choose General MIDI or a saved profile, edit drum/articulation-to-note mappings, and import or export profiles as CSV. Saved profiles are stored in the shared MagDrum sample database and the selected profile is also stored with the Cubase plug-in state. The current sequencer pattern, tempo, length, meter and edited MIDI metadata are stored with that state too. Profiles apply to MIDI file import/export; the drum-machine pads and incoming Cubase MIDI remain on their named General MIDI notes so assigning a sample to a pad does not change its playing note.

## Install and rescan

For a per-user install, double-click `Install-MagDrum-User.cmd`. It writes to `%LOCALAPPDATA%\Programs\Common\VST3` without elevation and backs up the previous user copy under `%LOCALAPPDATA%\MagDrum\VST3-backups`. VST3 hosts prioritize that user path over the global Program Files path. If an old system-wide MagDrum copy exists, the installer can request one UAC approval to move it and other old MagDrum bundles to `%ProgramData%\MagDrum\VST3-backups`; after that migration, per-user updates run without UAC. The no-UAC path requires the bundled Visual C++ runtime to already be installed. For a system-wide install or replacement at `C:\Program Files\Common Files\VST3\MagDrum.vst3`, use `Install-MagDrum.cmd` and approve standard Windows UAC. Start Cubase and choose **Studio > VST Plug-in Manager > Rescan All**.

## Instrument discovery progress and recovery

Choose **Plugin Scanner** to search for VST3 instruments. The status area shows the discovered instrument candidates and scan percentage. MagDrum caches plugin descriptions and skips unchanged modules on later refreshes; effect-only bundles are excluded whenever their VST3 manifest or cached description identifies them as effects. Discovery runs in the bundled helper, outside Cubase. The helper saves each completed module and JUCE records any module that crashes; MagDrum automatically restarts the helper to continue with the remaining plugins. A failing third-party plugin therefore cannot close Cubase or erase already discovered instruments.

## Instrument discovery cache

The VST3 instrument scan reads each module's `moduleinfo.json` to skip effect-only plugins before loading binaries. It stores the decision alongside the metadata path, file size and modification time; subsequent scans reuse unchanged classifications, and changed manifests are reclassified even when the plugin binary timestamp is unchanged. If a module changes from instrument to effect, stale cached instrument entries are removed. This reduces repeat scans of large effect suites such as Waves while keeping discovery focused on instruments. During a scan, the progress line shows the current candidate module as well as the completion percentage.
