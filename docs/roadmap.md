# Roadmap

1. **Library foundation — in progress:** standalone JUCE app, recursive WAV/AIFF/FLAC decoding where supported, SQLite index, stable folder/plugin source records linked separately from sample paths, filename/folder/tag search, all planned drum-category filters, plugin/source and kit filters, plugin-preview MIDI note/velocity/articulation labels, measured duration and spectral-brightness band filters, name/duration/brightness sorting, audition, selected-sample waveform, side-by-side waveform comparison, exact hash duplicate lookup, four-segment/16-band normalized acoustic fingerprints and ranked near-duplicate candidates, cancellation, scan history and restartable incremental scans. Desktop and mobile sample results are fetched from SQLite in pages of 250; desktop text/tag, category, source/kit, feature, review and sort filters run in a debounced background database query. Each completed file is committed to SQLite during the scan; interrupted scans are marked on next app launch and can skip already analyzed files on rescan. Windows smoke tests simulate a scan interruption and verify this recovery. Existing files are skipped when size, modification time and analysis version match. Analysis extracts duration, channels, sample rate, bit depth, peak, RMS, four-window spectral centroid, transient strength, a confidence-gated autocorrelation pitch estimate, file SHA-256 and an acoustic fingerprint. The versioned four-window measurement replaces the former first-window-only centroid and causes existing samples to be reanalyzed once. Better analysis on varied real-world signals, richer comparisons, and near-duplicate ranking evaluation on a labeled corpus remain.
2. **Audio intelligence — prototype:** filename-aware deterministic drum-family heuristics use whole-word matches to avoid substring false positives, behind an injectable classifier-model interface, descriptive tags, manual category correction, user tags, feature-distance similarity query and ranked near-duplicate candidates. Conflicting filename cues stay Unknown. Feature-only kick classification now requires transient energy and avoids samples with a confident high fundamental; synthetic tone and low-transient checks guard against obvious false positives. The browser shows each sample's heuristic confidence and provides a review filter for uncorrected Unknown or below-75% results; manually corrected samples are excluded. The threshold is an uncalibrated review aid. Classification quality on real libraries, feature coverage across short files, candidate evaluation, trained model inference and confidence calibration still need work.
3. **Instrument scanning — manual scan workflow implemented:** the desktop app discovers installed instrument plugins, loads a selected instrument asynchronously, enumerates and lets users select programs exposed through the plugin API, finds VST3 presets in platform-standard vendor/plugin folders or a user-selected folder, and asks the selected instrument to recall one. It saves the named plugin state. Captured plugin previews can reopen their installed source instrument and recall its saved kit state. Instruments without an exposed program list still use manual kit selection in the editor. Users can choose offline-fast rendering, realtime-marked wall-clock pacing, or a system audio-device callback fallback. The callback path opens the default output device in the isolated worker, captures at the device's sample rate, and routes audio to its outputs. A virtual callback-driven test verifies MIDI scheduling and captured audio, but physical driver operation and commercial instrument behavior still need validation. Scans render MIDI notes 0–127 at configured velocity levels, repeat counts and note/release/capture lengths, report progress, support cancellation, detect silence, restore plugin state, analyze generated previews, and store each audible take in SQLite and the sample browser. Completed captures and metadata are streamed to disk, so a worker crash preserves finished takes and the parent process recovers and indexes them. Windows tests verify realtime pacing, capture sample-rate metadata, callback rendering and worker recovery after an abort following a completed capture. It compares acoustic fingerprints between adjacent sampled velocity levels and repeated takes, storing versioned heuristic layer-boundary and round-robin variation candidates. Users can review candidate data, record non-overlapping velocity ranges, and confirm or remove exact round-robin take groups after listening; these declarations remain distinct from algorithmic results. Recovery from an actual third-party VST3 fault and capture quality across commercial instruments remain unverified.
4. **MIDI compatibility — desktop core implemented:** semantic drum events, GM and editable custom mapping profiles, explicit fallback results, mapping persistence, validated CSV profile import/export, note import/export, tempo/signature event preservation and a drum-event editor are implemented. Unmapped imported notes and ambiguous note-to-semantics assignments are reported by note number and event count; ambiguity reports list the candidates and identify the deterministic first mapping used. Omitted export events are listed. Users can review, set and remove tempo or time-signature changes at any beat while retaining the other events. The editor compares an imported pattern with its current state, including note events, tempo/meter metadata and pattern length. Broader real-world timing/round-trip review remains.
5. **Platform products — partial:** the VST3 sampler lets users load indexed or local WAV/AIFF/FLAC-decoded samples onto MIDI notes, assign up to eight non-overlapping velocity ranges per note, and clear a note's layers. It selects a layer from incoming MIDI velocity and persists range/path state while continuing to read the older single-sample state format. Sample buffers are swapped without blocking the audio callback. Plugin smoke tests cover range selection, overlap rejection, velocity response, and state restoration. `Build-Windows.ps1` has built, tested and packaged Windows x64 locally; the latest local package can be installed without a release upload. The five desktop targets are Windows x64/ARM64, macOS Intel/Apple Silicon AU/VST3, and Linux x64. Actions billing prevents hosted matrix verification. Windows ARM64 tools are not detected yet, WSL/Linux is not configured, and Apple targets need a Mac. macOS/Linux local build scripts have not been exercised on their target hosts. An initial iOS/AUv3 source target and a Windows desktop preview of its shared C++ compile successfully, but Apple SDK builds, app-group entitlements, device behavior, signing and packaging remain unverified.
6. **Advanced analysis — prototype:** an eight-lane sequencer can append a bar using the pattern's current time signature when it fits the 16-step grid. It retains pattern length, including empty bars, through Standard MIDI File end-of-track timing. Left-click toggles hits; right-click assigns any velocity from 1–127, with a shared default for untouched steps. It exports through the existing MIDI writer. Preview renders a tempo-aware WAV from the first indexed sample in each matching drum category, then plays it through the desktop audio transport. Looping can be toggled in the sequencer while playing; the audio source wraps at the rendered preview boundary using an atomic control flag. Tempo-change, loop-boundary, audible-output and cancellation cleanup are covered by smoke tests. Plugin scans suggest velocity-layer boundaries and repeated-trigger variation from acoustic fingerprint changes, and users can now record separate confirmed velocity ranges and exact round-robin take groups after listening. Better kit/sample matching, model-assisted classification, articulation detection and evaluation on labeled data remain.

## Completion criteria

The product is not complete until each supported platform has a reproducible build and install package, library/MIDI behavior has been reviewed against broader real-world collections, candidate similarity has been evaluated on labeled examples, and the advanced planned workflows are implemented. Sample scanning can be safely restarted after an interruption; it does not resume at an exact in-progress file. AUv3/iOS and model-assisted analysis need Apple/mobile and model evaluation work respectively; they are not represented by the desktop CI results. GitHub Pages is not enabled for this private repository, so the checked-in website source is not currently hosted.

Desktop VST3 scanning is not an iOS requirement.
