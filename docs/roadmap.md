# Roadmap

1. **Library foundation — in progress:** standalone JUCE app, recursive WAV/AIFF/FLAC decoding where supported, SQLite index, stable folder/plugin source records linked separately from sample paths, filename/folder/tag search, all planned drum-category filters, plugin/source and kit filters, plugin-preview MIDI note/velocity/articulation labels, measured duration and spectral-brightness band filters, name/duration/brightness sorting, audition, selected-sample waveform, side-by-side waveform comparison, exact hash duplicate lookup, four-segment/16-band normalized acoustic fingerprints and ranked near-duplicate candidates, cancellation, scan history and restartable incremental scans. Existing files are skipped when size, modification time and analysis version match; interrupted scan sessions are marked on next app launch, so rescanning fills in missing, changed or newly analyzed files. Analysis extracts duration, channels, sample rate, bit depth, peak, RMS, four-window spectral centroid, transient strength, a confidence-gated autocorrelation pitch estimate, file SHA-256 and an acoustic fingerprint. The versioned four-window measurement replaces the former first-window-only centroid and causes existing samples to be reanalyzed once. Better analysis on varied real-world signals, richer comparisons, and near-duplicate ranking evaluation on a labeled corpus remain.
2. **Audio intelligence — prototype:** filename-aware deterministic drum-family heuristics behind an injectable classifier-model interface, descriptive tags, manual category correction, user tags, feature-distance similarity query and ranked near-duplicate candidates. Conflicting filename cues stay Unknown. The browser shows each sample's heuristic confidence and provides a review filter for uncorrected Unknown or below-75% results; manually corrected samples are excluded. The threshold is an uncalibrated review aid. Classification quality, feature coverage across short files, candidate evaluation, trained model inference and confidence calibration still need work.
3. **Instrument scanning — manual scan workflow implemented:** the desktop app discovers installed instrument plugins, loads a selected instrument asynchronously, enumerates and lets users select programs exposed through the plugin API, finds VST3 presets in platform-standard vendor/plugin folders or a user-selected folder, and asks the selected instrument to recall one. It saves the named plugin state. Captured plugin previews can reopen their installed source instrument and recall its saved kit state. Instruments without an exposed program list still use manual kit selection in the editor. An explicit offline scan renders MIDI notes 0–127 at configured velocity levels, repeat counts and note/release/capture lengths, reports progress, supports cancellation, detects silence, restores plugin state, analyzes generated previews, and stores each audible take in SQLite and the sample browser. It compares acoustic fingerprints between adjacent sampled velocity levels and repeated takes, storing versioned heuristic layer-boundary and round-robin variation candidates; the scan summary reports them and dedicated buttons reopen each list for listening review. Note rendering runs in a child process so a plugin crash or hang does not take down the main app. End-to-end crash recovery with third-party instruments still needs a fixture, and external plugin capture quality still depends on each instrument.
4. **MIDI compatibility — desktop core implemented:** semantic drum events, GM and editable custom mapping profiles, explicit fallback results, mapping persistence, validated CSV profile import/export, note import/export, tempo/signature event preservation and a drum-event editor are implemented. Unmapped imported notes and ambiguous note-to-semantics assignments are reported by note number and event count; ambiguity reports list the candidates and identify the deterministic first mapping used. Omitted export events are listed. Users can review, set and remove tempo or time-signature changes at any beat while retaining the other events. Broader real-world timing/round-trip review and a side-by-side MIDI diff remain.
5. **Platform products — partial:** current VST3 source lets users load WAV/AIFF/FLAC-decoded samples onto MIDI notes and persists those paths in plugin state. Sample buffers are swapped without blocking the audio callback. `Build-Windows.ps1` has built, tested and packaged Windows x64 locally; the resulting prerelease was uploaded with GitHub CLI without starting Actions. The five desktop targets are Windows x64/ARM64, macOS Intel/Apple Silicon AU/VST3, and Linux x64. Actions billing prevents hosted matrix verification. Windows ARM64 tools are not detected yet, WSL/Linux is not configured, and Apple targets need a Mac. macOS/Linux local build scripts have not been exercised on their target hosts. Code signing, AUv3/iOS targets and mobile library UX remain.
6. **Advanced analysis — prototype:** an eight-lane sequencer can append a bar using the pattern's current time signature when it fits the 16-step grid. It retains pattern length, including empty bars, through Standard MIDI File end-of-track timing. Left-click toggles hits; right-click assigns any velocity from 1–127, with a shared default for untouched steps. It exports through the existing MIDI writer. Preview renders a tempo-aware WAV from the first indexed sample in each matching drum category, then plays it through the desktop audio transport. Looping can be toggled in the sequencer while playing; the audio source wraps at the rendered preview boundary using an atomic control flag. Tempo-change, loop-boundary, audible-output and cancellation cleanup are covered by smoke tests. Plugin scans suggest velocity-layer boundaries and repeated-trigger variation from acoustic fingerprint changes. Better kit/sample matching, model-assisted classification, articulation detection, confirmed layer ranges and evaluation on labeled data remain.

## Completion criteria

The product is not complete until each supported platform has a reproducible build and install package, library/MIDI behavior has been reviewed against broader real-world collections, candidate similarity has been evaluated on labeled examples, and the advanced planned workflows are implemented. Sample scanning can be safely restarted after an interruption; it does not resume at an exact in-progress file. AUv3/iOS and model-assisted analysis need Apple/mobile and model evaluation work respectively; they are not represented by the desktop CI results. GitHub Pages is not enabled for this private repository, so the checked-in website source is not currently hosted.

Desktop VST3 scanning is not an iOS requirement.
