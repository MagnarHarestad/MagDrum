# Roadmap

1. **Library foundation — in progress:** standalone JUCE app, recursive WAV/AIFF/FLAC decoding where supported, SQLite index, filename/folder/tag search, all planned drum-category filters, audition, selected-sample waveform, side-by-side waveform comparison, exact hash duplicate lookup, cancellation, scan history and restartable incremental scans. Existing files are skipped when saved size and modification time match; interrupted scan sessions are marked on next app launch, so scanning the folder again fills in missing or changed files. Analysis extracts duration, channels, sample rate, bit depth, peak, RMS, one-window spectral centroid, transient strength, a confidence-gated autocorrelation pitch estimate and file SHA-256. Hashes identify exact duplicates; perceptual duplicate grouping still needs work.
2. **Audio intelligence — prototype:** deterministic low-confidence drum-family heuristics, manual category correction, user tags and feature-distance similarity query. Classification quality, feature coverage across short files, perceptual duplicate workflow, and confidence review still need work.
3. **Instrument scanning — manual scan workflow implemented:** the desktop app discovers installed instrument plugins, loads a selected instrument asynchronously, lets the user choose a kit in the plugin editor, and saves the named plugin state. An explicit offline scan renders MIDI notes 0–127 at configured velocity levels and note/release/capture lengths, reports progress, supports cancellation, detects silence, restores plugin state, analyzes generated previews, and stores them in SQLite and the sample browser. Plugin crashes are not isolated in a separate process, presets are not discovered automatically, and external plugin capture quality still depends on each instrument.
4. **MIDI compatibility — desktop core implemented:** semantic drum events, GM and editable custom mapping profiles, explicit fallback results, mapping persistence, validated CSV profile import/export, note import/export and tempo/signature event preservation are implemented. Unmapped imported notes are reported by note number and event count; omitted export events are listed. A MIDI event editor and broader timing/round-trip review remain.
5. **Platform products — partial:** current VST3 source lets users load WAV/AIFF/FLAC-decoded samples onto MIDI notes and persists those paths in plugin state. Sample buffers are swapped without blocking the audio callback. Standalone desktop, Windows/Linux/macOS VST3, and macOS AU build targets exist; CI currently compiles the desktop targets. Windows x64 is the only prepared installer. macOS AU/VST3 and Linux archives, code signing, Intel macOS validation, AUv3/iOS targets, and mobile library UX remain.
6. **Advanced analysis — not implemented:** model-assisted classification, articulation detection, velocity-layer inference, tempo synchronization and a step sequencer.

## Completion criteria

The product is not complete until each supported platform has a reproducible build and install package, the remaining library/MIDI review, perceptual duplicate grouping and reporting features are implemented, and the advanced planned workflows are implemented. Sample scanning can be safely restarted after an interruption; it does not resume at an exact in-progress file. AUv3/iOS and model-assisted analysis need Apple/mobile and model evaluation work respectively; they are not represented by the desktop CI results.

Desktop VST3 scanning is not an iOS requirement.
