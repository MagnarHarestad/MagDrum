2. **Audio intelligence — prototype:** filename-aware deterministic drum-family heuristics use whole-word matches to avoid substring false positives; exact category folder labels among the nearest five parent directories add a separate 0.84-confidence hint, and conflicting file/folder cues remain Unknown. These heuristics sit behind an injectable classifier-model interface. Descriptive classifier tags are stored separately from user tags, searchable and shown in desktop/mobile sample rows; users can still add their own tags. Bright and Dark tags also use measured spectral centroid, Short uses measured duration independent of loudness or bit depth, and common distortion filename forms normalize to Distorted. Filename cues add articulation labels for ghost notes, flams, rolls, brushes, rimshot/stick techniques, and cymbal bow/bell/edge and half-open hi-hat playing. The waveform analysis also emits tentative Flam and Roll candidates when detected attack timing matches conservative count and spacing patterns; these are heuristic candidates, not confirmed technique labels. The app also supports manual category correction, feature-distance similarity query and ranked near-duplicate candidates. Conflicting filename cues stay Unknown. Feature-only Kick suggestions use transient energy, a sample duration below three seconds and low spectral centroid, and avoid samples with a confident higher fundamental. Tom suggestions use a reliable 95–380 Hz pitch or, when pitch is uncertain, a 350–1250 Hz centroid, 1.5–6 second decay and transient checks. Acoustic-only category suggestions remain below the 0.75 review threshold. Spectral flatness distinguishes noise-like unpitched short/long hi-hat fixtures from tonal snare fixtures. A low-confidence Clap suggestion now also uses repeated transient attacks, brightness, flatness, duration and transient ratio; its generated four-pulse WAV fixture validates the measured path, not broad real-library accuracy. A local example-matching model learns from manually corrected database rows and chooses the four-window/16-band acoustic fingerprint weight (0.10, 0.25 or 0.50) using category-stratified inner leave-one-out validation on up to eight examples per category, with query filenames hidden. It only suggests a category below the 75% review threshold when at least two nearby examples agree, and never overwrites a manual category. Filename-hidden nested leave-one-sample-out testing scored 65.9% accuracy / 0.618 macro F1 on the 44-sample three-kit corpus and 70.2% / 0.707 on the 121-sample single-kit corpus. Leave-one-kit-out testing on the three-kit corpus scored 38.6% / 0.356, so cross-kit generalization remains weak. These folder-label comparisons are not calibrated probabilities or listener-verified quality. The optional `MagDrumClassifierEvaluation` tool reports per-class precision/recall/F1, separates filename-assisted from audio-only results, and evaluates production near-duplicate candidates against labeled folders. The synthetic smoke and external CC0 corpus runs verify the report and retrieval paths, not general model or listener quality. The browser shows each sample's heuristic confidence and provides a review filter for uncorrected Unknown or below-75% results; manually corrected samples are excluded. The threshold is an uncalibrated review aid. Earlier audio-only measurements scored 25.0% / 0.196 on a 44-file three-kit corpus, 14.1% / 0.083 on a 128-file jazz-kit subset, and 2.5% / 0.007 on a 121-file subset from another kit. The updated acoustic fallback rules raise that last result to 22.3% / 0.212, while the updated 52-file three-kit audio-only result is 44.2% / 0.320, up from 32.7% / 0.272; neither the updated three-kit corpus nor the 121-file corpus produced audio-only suggestions at the 0.75 review threshold. Filename-assisted results were 68.2%, 100.0% and 86.8% on those respective corpora, influenced by category words in the filenames; the prior 121-file measurement had macro F1 0.848 after adding SFZ Tom-family codes; a follow-up added exact percussion instrument names such as Agogo and scored 100.0% / 1.000 on filename-plus-audio classification, while audio-only remains 22.3% / 0.212. See `docs/classifier-evaluation.md` for provenance and full measurements. The exact `808s` folder contributes a Kick review hint; `htom`, `ltom`, `tomhi` and `tomlo` identify SFZ Tom families. Conflicting filename/folder cues remain Unknown. The results show that the current heuristic is not dependable for audio-only classification. Generic HiHat/HH filename cues now remain Unknown with a searchable Hi-hat tag unless the file or audio provides a more specific distinction; SFZ hi-hat names in either order, including `kickmic_hh_closed/open/pedal`, map to their corresponding category. On the 121-file CC0 Virtuosity subset, adding this token-order support raised filename-plus-audio accuracy from 68.6% to 100%; audio-only remained 22.3%, so this confirms filename recognition rather than acoustic generalization. Conflicting open/closed filename cues remain Unknown. Broader labeled collections, human review of retrieved candidates and calibrated confidence still need work.
3. **Instrument scanning — manual scan workflow implemented:** the desktop app discovers installed instrument plugins, loads a selected instrument asynchronously, enumerates and lets users select programs exposed through the plugin API, finds VST3 presets in platform-standard vendor/plugin folders or a user-selected folder, and asks the selected instrument to recall one. It saves the named plugin state. Captured plugin previews can reopen their installed source instrument and recall its saved kit state. Instruments without an exposed program list still use manual kit selection in the editor. Users can choose offline-fast rendering, realtime-marked wall-clock pacing, or a system audio-device callback fallback. The callback path opens the default output device in the isolated worker, captures at the device's sample rate, and routes audio to its outputs. A virtual callback-driven test verifies MIDI scheduling and captured audio, but physical driver operation and commercial instrument behavior still need validation. Scans render MIDI notes 0–127 at configured velocity levels, repeat counts and note/release/capture lengths, report progress, support cancellation, detect silence, restore plugin state, analyze generated previews, and store each audible take in SQLite and the sample browser. Completed captures and metadata are streamed to disk, so a worker crash preserves finished takes and the parent process recovers and indexes them. Windows tests verify realtime pacing, capture sample-rate metadata, callback rendering and worker recovery after an abort following a completed capture. An end-to-end fixture now hosts the built MagDrum VST3 in a separate worker, restores its saved sample state, scans the full MIDI range, and confirms an audible note-36 WAV capture. The worker also replaces its default velocity with the requested levels rather than appending to it. The app compares acoustic fingerprints between adjacent sampled velocity levels and repeated takes, storing versioned heuristic layer-boundary and round-robin variation candidates. Users can review candidate data, record non-overlapping velocity ranges, and confirm or remove exact round-robin take groups after listening; these declarations remain distinct from algorithmic results. Recovery and capture quality with third-party VST3 instruments remain unverified.
4. **MIDI compatibility — desktop core implemented, mobile profile controls added:** semantic drum events, GM and editable custom mapping profiles, explicit fallback results, mapping persistence, validated CSV profile import/export, note import/export, tempo/signature event preservation and a drum-event editor are implemented. Unmapped imported notes and ambiguous note-to-semantics assignments are reported by note number and event count; ambiguity reports list the candidates and identify the deterministic first mapping used. Omitted export events are listed. Users can review, set and remove tempo or time-signature changes at any beat while retaining the other events. The editor compares an imported pattern with its current state, including note events, tempo/meter metadata and pattern length. The mobile app can select and edit named MIDI profiles stored in SQLite. A deterministic round-trip suite now writes and rereads 24 generated patterns containing 1,536 semantic note events, custom target mappings, varied velocities, PPQ-grid positions, and tempo/meter changes; every pattern compares equal after import. A Windows regression also verifies that overlapping same-pitch notes split across MIDI tracks retain their distinct durations when imported. Review against broader third-party MIDI files, DAW round-trips and Apple-device behavior remains.

6. **Advanced analysis — prototype:** a sixteen-lane sequencer can append a bar using the pattern's current time signature when it fits the 16-step grid. It retains pattern length, including empty bars, through Standard MIDI File end-of-track timing. Left-click toggles hits; right-click assigns any velocity from 1–127, with a shared default for untouched steps. It exports through the existing MIDI writer. Preview renders a tempo-aware WAV from the first indexed sample in each matching drum category, then plays it through the desktop audio transport. Looping can be toggled in the sequencer while playing; the audio source wraps at the rendered preview boundary using an atomic control flag. Tempo-change, loop-boundary, audible-output and cancellation cleanup are covered by smoke tests. Plugin scans suggest velocity-layer boundaries and repeated-trigger variation from acoustic fingerprint changes, and users can now record separate confirmed velocity ranges and exact round-robin take groups after listening. A manual, versioned JSON metadata archive and opt-in metadata folder sync are implemented in the standalone app and VST for user tags, manual categories and MIDI mapping profiles. Folder sync writes one snapshot per device to a user-selected provider-managed folder and imports the other device snapshots; sample metadata matches on local content hash and size. It never copies live SQLite databases, audio, local paths or plugin states. All snapshots are merged transactionally; limits are 128 device archives and 256 MB total, with 128 MB per file. Conflicting categories and MIDI profiles are preserved and reported. Folder sync version 2 now carries observed-remove tag operations: deletion propagates, independent additions converge, and a concurrent re-add survives an older removal. Version 1 snapshots remain additive for compatibility. Provider APIs, automatic scheduling, transfer completion reporting, encryption and collaborator/retention policy remain open. Better kit/sample matching, model-assisted classification, acoustic articulation detection and human evaluation on labeled data remain.
