# Roadmap

**Windows VST3 workflow in progress:** the editor has five views: a categorized sample map, a Boss DR-660 4×4 GM drum machine with Kick, Snare, Pedal HH and Cowbell on the bottom row, waveform and velocity layers, a selectable 1–16-bar sequencer with editable step velocities and MIDI import/export, MIDI mapping profiles, and a plugin scan workspace. The Plugin Scanner discovers VST3 plugins from standard system/user locations in an isolated MagDrum helper. Windows packages place the helper beside the VST3 module; the Linux package now carries it in the VST3 resources bundle, while macOS packaging has matching bundle-copy logic awaiting a Mac build. Linux helper launch and instrument-host isolation still require native DAW validation. It can list programs exposed by a selected instrument and save a selected program as a kit; it can also import a chosen `.vstpreset`, save its state as a kit, select saved kits, configure note/velocity capture and run an isolated MIDI scan. Results enter the shared sample library with velocity-layer and round-robin analysis. The standalone manager is still needed to interact with plugin-specific editors and manually select kits when the instrument exposes no program list or preset file. The shared app/VST UI uses an overhead-lit textured charcoal background, beveled and textured button faces, cyan glow text and active/pushed indicators, and glossy cyan-ring rotary controls. The Drum Machine page now exposes per-MIDI-note Gain (-60 to +6 dB), Pan (-1 to +1) and Tune (-24 to +24 semitones), saved in plugin state and applied to each triggered sample voice. Windows and Linux Release CTest suites pass for the control implementation on 2026-11-15. Manual Cubase Pro 15 interaction review remains. Other platforms remain incomplete: Windows ARM64 needs native runtime testing, and Linux/macOS builds require their target hosts.

1. **Library foundation — in progress:** standalone JUCE app, recursive WAV/AIFF/FLAC decoding where supported, SQLite index, stable folder/plugin source records linked separately from sample paths, filename/folder/tag search, all planned drum-category filters, plugin/source and kit filters, plugin-preview MIDI note/velocity/articulation labels, measured duration and spectral-brightness band filters, name/duration/brightness sorting, audition, selected-sample waveform, side-by-side waveform comparison, exact hash duplicate lookup, four-segment/16-band normalized acoustic fingerprints and ranked near-duplicate candidates, cancellation, scan history and restartable incremental scans. Desktop and mobile sample results are fetched from SQLite in pages of 250; desktop text/tag, category, source/kit, feature, review and sort filters run in a debounced background database query. Each completed file is committed to SQLite with a stable path-order checkpoint. After cancellation or restart, rescanning the same folder continues after the last completed audio file; if interruption occurred mid-file, that file is safely retried. The Windows smoke test verifies cursor persistence and confirms the resumed pass processes only the next file. They generate WAV, AIFF and FLAC fixtures with JUCE and verify that all three decode into indexed measurements; other operating systems and broader real-world libraries still need verification. Existing files are skipped when size, modification time and analysis version match. Analysis extracts duration, channels, sample rate, bit depth, peak, RMS, four-window spectral centroid and spectral flatness, transient strength and attack timing, a confidence-gated autocorrelation pitch estimate, file SHA-256 and an acoustic fingerprint. Version 4 populates classifier and filename-derived articulation tags for existing libraries. Analysis version 5 added spectral flatness; version 6 adds transient attack count; version 7 recognizes additional common SFZ family codes and reanalyzes existing samples while preserving manual categories and user tags; version 8 stores detected attack times for audio-based flam/roll candidates. The versioned four-window measurement replaces the former first-window-only centroid. A synthetic labeled similarity fixture now checks gain variants across four tone families: precision and recall are both 100% for these eight controlled queries. The optional evaluator measures production near-duplicate candidate category agreement against folder labels. Two CC0 library evaluations found 55.6% and 89.8% category agreement; the higher score is from velocity/repetition variants within a single kit. These are weak label proxies, not listener validation. More diverse libraries, human review and cross-operating-system format verification remain.
2. **Audio intelligence — prototype:** filename-aware deterministic drum-family heuristics use whole-word matches to avoid substring false positives; exact category folder labels among the nearest five parent directories add a separate 0.84-confidence hint, and conflicting file/folder cues remain Unknown. These heuristics sit behind an injectable classifier-model interface. Descriptive classifier tags are stored separately from user tags, searchable and shown in desktop/mobile sample rows; users can still add their own tags. Bright and Dark tags also use measured spectral centroid, Short uses measured duration independent of loudness or bit depth, and common distortion filename forms normalize to Distorted. Filename cues add articulation labels for ghost notes, flams, rolls, brushes, rimshot/stick techniques, and cymbal bow/bell/edge and half-open hi-hat playing. The waveform analysis also emits tentative Flam and Roll candidates when detected attack timing matches conservative count and spacing patterns; these are heuristic candidates, not confirmed technique labels. The app also supports manual category correction, feature-distance similarity query and ranked near-duplicate candidates. Conflicting filename cues stay Unknown. Feature-only Kick suggestions use transient energy, a sample duration below three seconds and low spectral centroid, and avoid samples with a confident higher fundamental. Tom suggestions use a reliable 95–380 Hz pitch or, when pitch is uncertain, a 350–1250 Hz centroid, 1.5–6 second decay and transient checks. Acoustic-only category suggestions remain below the 0.75 review threshold. Spectral flatness distinguishes noise-like unpitched short/long hi-hat fixtures from tonal snare fixtures. A low-confidence Clap suggestion now also uses repeated transient attacks, brightness, flatness, duration and transient ratio; its generated four-pulse WAV fixture validates the measured path, not broad real-library accuracy. A local example-matching model learns from manually corrected database rows and chooses the four-window/16-band acoustic fingerprint weight (0.10, 0.25 or 0.50) using category-stratified inner leave-one-out validation on up to eight examples per category, with query filenames hidden. It only suggests a category below the 75% review threshold when at least two nearby examples agree, and never overwrites a manual category. Filename-hidden nested leave-one-sample-out testing scored 65.9% accuracy / 0.618 macro F1 on the 44-sample three-kit corpus and 70.2% / 0.707 on the 121-sample single-kit corpus. Leave-one-kit-out testing on the three-kit corpus scored 38.6% / 0.356, so cross-kit generalization remains weak. These folder-label comparisons are not calibrated probabilities or listener-verified quality. The optional `MagDrumClassifierEvaluation` tool reports per-class precision/recall/F1, separates filename-assisted from audio-only results, and evaluates production near-duplicate candidates against labeled folders. The synthetic smoke and external CC0 corpus runs verify the report and retrieval paths, not general model or listener quality. The browser shows each sample's heuristic confidence and provides a review filter for uncorrected Unknown or below-75% results; manually corrected samples are excluded. The threshold is an uncalibrated review aid. Earlier audio-only measurements scored 25.0% / 0.195 on a 44-file three-kit corpus, 14.1% / 0.083 on a 128-file jazz-kit subset, and 2.5% / 0.007 on a 121-file subset from another kit. The updated acoustic fallback rules raise that last result to 22.3% / 0.212, while the three-kit result remains 25.0% / 0.195; neither corpus produced audio-only suggestions at the 0.75 review threshold. Filename-assisted results were 68.2%, 100.0% and 84.3% on those respective corpora, influenced by category words in the filenames. See `docs/classifier-evaluation.md` for provenance and full measurements. The results show that the current heuristic is not dependable for audio-only classification. Broader labeled collections, human review of retrieved candidates and calibrated confidence still need work.
3. **Instrument scanning — manual scan workflow implemented:** the desktop app discovers installed instrument plugins, loads a selected instrument asynchronously, enumerates and lets users select programs exposed through the plugin API, finds VST3 presets in platform-standard vendor/plugin folders or a user-selected folder, and asks the selected instrument to recall one. It saves the named plugin state. Captured plugin previews can reopen their installed source instrument and recall its saved kit state. Instruments without an exposed program list still use manual kit selection in the editor. Users can choose offline-fast rendering, realtime-marked wall-clock pacing, or a system audio-device callback fallback. The callback path opens the default output device in the isolated worker, captures at the device's sample rate, and routes audio to its outputs. A virtual callback-driven test verifies MIDI scheduling and captured audio, but physical driver operation and commercial instrument behavior still need validation. Scans render MIDI notes 0–127 at configured velocity levels, repeat counts and note/release/capture lengths, report progress, support cancellation, detect silence, restore plugin state, analyze generated previews, and store each audible take in SQLite and the sample browser. Completed captures and metadata are streamed to disk, so a worker crash preserves finished takes and the parent process recovers and indexes them. Windows tests verify realtime pacing, capture sample-rate metadata, callback rendering and worker recovery after an abort following a completed capture. An end-to-end fixture now hosts the built MagDrum VST3 in a separate worker, restores its saved sample state, scans the full MIDI range, and confirms an audible note-36 WAV capture. The worker also replaces its default velocity with the requested levels rather than appending to it. The app compares acoustic fingerprints between adjacent sampled velocity levels and repeated takes, storing versioned heuristic layer-boundary and round-robin variation candidates. Users can review candidate data, record non-overlapping velocity ranges, and confirm or remove exact round-robin take groups after listening; these declarations remain distinct from algorithmic results. Recovery and capture quality with third-party VST3 instruments remain unverified.
4. **MIDI compatibility — desktop core implemented, mobile profile controls added:** semantic drum events, GM and editable custom mapping profiles, explicit fallback results, mapping persistence, validated CSV profile import/export, note import/export, tempo/signature event preservation and a drum-event editor are implemented. Unmapped imported notes and ambiguous note-to-semantics assignments are reported by note number and event count; ambiguity reports list the candidates and identify the deterministic first mapping used. Omitted export events are listed. Users can review, set and remove tempo or time-signature changes at any beat while retaining the other events. The editor compares an imported pattern with its current state, including note events, tempo/meter metadata and pattern length. The mobile app can select and edit named MIDI profiles stored in SQLite. A deterministic round-trip suite now writes and rereads 24 generated patterns containing 1,536 semantic note events, custom target mappings, varied velocities, PPQ-grid positions, and tempo/meter changes; every pattern compares equal after import. Review against broader third-party MIDI files, DAW round-trips and Apple-device behavior remains.
5. **Platform products — partial:** the VST3 sampler loads indexed samples and provides a local WAV/AIFF/FLAC file picker directly in the plugin, assigns up to eight non-overlapping velocity layers per note, and persists assignments plus per-note gain, pan and pitch. Pad and sequencer GUI triggers use a bounded lock-free queue into the audio callback. The desktop Plugin Scanner discovers instruments, imports exposed programs or `.vstpreset` files as named kits, and performs note/velocity scans in an isolated helper; captured samples and layer/round-robin candidates enter the shared library. Windows packages place the helper beside the VST3 module; Linux now packages it under `Contents/Resources`; the Linux archive passes dependency checks, and the integration test launches the same MagDrum app binary as the isolated scanner, scans all 128 notes from the built MagDrum VST3 and verifies audible note 36. Third-party instruments and native DAW runtime remain unverified. macOS package code copies the helper into VST3 and AU bundles but is not built until a Mac is available. Opening a third-party instrument's own editor still launches a separate MagDrum manager. Sequencer meter changes are represented on sixteenth-note boundaries and preserved in MIDI export; finer changes remain unsupported in the grid. Public release [v0.1.1-test.152](https://github.com/MagnarHarestad/MagDrum/releases/tag/v0.1.1-test.152) contains Windows x64, Windows ARM64 and Linux x64; the public website is synced. Windows x64 and Linux Release CTest suites pass 2/2; both suites cover the schema-17 FTS5 rebuild and indexed search at 250,000 rows; plugin smoke tests decode and render AIFF and FLAC. The user-example model calibrates its fingerprint weight from manual examples with query filenames hidden. ARM64 package executables identify as ARM64, but native runtime and test-suite results are unverified. The system VST3 folder still contains .135. Windows reports hidden Cubase15.exe PID 20148, so the installer cannot replace the plugin yet. Once that process exits, the installer moves .135 outside the VST3 scan folder; Cubase rescan and manual interaction remain pending. Previous bundles are kept outside the VST3 scan folder. Linux JUCE-host tests load the release plugin, scan MIDI notes 0–127 and confirm an audible note 36 after restoring state; Ardour 8.4 recognizes the package in Ubuntu 24.04 WSL2, but interactive DAW and physical audio-device checks remain. Plugin editor, standalone browser and auxiliary-window controls refresh translations live; all 543 source labels have entries in the seven non-English catalogs, and mobile scan/MIDI/tag strings are translated across all eight choices. Full runtime language review remains open. Windows ARM64 was cross-compiled on x64; JUCE omits its optional `moduleinfo.json`, and native execution remains unverified. Hosted Actions are unavailable due to billing. The iOS shared UI has a Windows desktop preview build, but Apple SDK compilation, entitlements, device behavior, signing and packaging are unverified; macOS and iOS products still require Apple hardware and SDKs.
6. **Advanced analysis — prototype:** an eight-lane sequencer can append a bar using the pattern's current time signature when it fits the 16-step grid. It retains pattern length, including empty bars, through Standard MIDI File end-of-track timing. Left-click toggles hits; right-click assigns any velocity from 1–127, with a shared default for untouched steps. It exports through the existing MIDI writer. Preview renders a tempo-aware WAV from the first indexed sample in each matching drum category, then plays it through the desktop audio transport. Looping can be toggled in the sequencer while playing; the audio source wraps at the rendered preview boundary using an atomic control flag. Tempo-change, loop-boundary, audible-output and cancellation cleanup are covered by smoke tests. Plugin scans suggest velocity-layer boundaries and repeated-trigger variation from acoustic fingerprint changes, and users can now record separate confirmed velocity ranges and exact round-robin take groups after listening. A manual, versioned JSON metadata archive is implemented for tags, manual categories and MIDI profiles. Import matches local files by content hash and size, unions tags, and reports conflicts without overwriting local categories or mapping profiles. It sends no audio or local paths and does not provide automatic/cloud sync; provider, sharing, encryption, tag-removal tombstones and conflict-resolution choices remain. Better kit/sample matching, model-assisted classification, acoustic articulation detection and human evaluation on labeled data remain.

## Completion criteria

**Localization verification update:** Windows plugin smoke coverage now checks representative drum-machine, sample-library and sorting labels in all eight language choices, including correct UTF-8 French accents. Full screen-by-screen language review remains pending.

`Build-Windows.ps1` now runs a localization source audit before building. It checks that all 543 translatable string literals passed to `localisedText` appear in each of the seven non-English catalogs; the audit passes on the current source tree. Windows plugin smoke coverage checks off-grid preservation and host-synchronized sequencer notices in all eight language choices.

The product is not complete until each supported platform has a reproducible build and install package, library/MIDI behavior has been reviewed against broader real-world collections, candidate similarity has been evaluated on labeled examples, and the advanced planned workflows are implemented. AUv3/iOS and model-assisted analysis need Apple/mobile and model evaluation work respectively; they are not represented by the desktop CI results. MagDrum's original code is licensed under AGPLv3. A target-by-target audit of JUCE modules, SDKs and required third-party notices remains before stable multi-platform distribution; see [licensing status](licensing.md). The public landing page is deployed at https://magnarharestad.github.io/MagDrum-Website/ from a separate public repository containing only the page and stylesheet; the application source repository is public. Releases synchronize the public landing page to the latest published test version.

Desktop VST3 scanning is not an iOS requirement.

The AUv3 editor layout keeps the sample library, drum machine, sequencer, MIDI maps and language menu, while omitting the desktop-only VST3 plugin scanner. `MAGDRUM_BUILD_MOBILE_PREVIEW=ON` compiles that editor layout in a Windows VST3 preview alongside the shared iOS library preview; the mobile-preview CTest suite passed 2/2 on 2026-11-15. This is compile validation only; AUv3 runtime behavior still requires Apple hardware and SDKs.
