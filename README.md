# MagDrum

MagDrum is a cross-platform drum sound library and MIDI mapping workspace. Browse WAV sample libraries alongside sounds from drum instruments, audition them, and transfer drum patterns through semantic MIDI mappings.

**MagDrum** is the product name. Formats are platform targets: VST3 on Windows, macOS and Linux; AU on macOS; AUv3 on iOS/iPadOS where supported. Phase 1 is a standalone app; it does not require a DAW or commercial instruments. The latest test release contains Windows x64 and ARM64 packages. The ARM64 app and VST3 have been cross-compiled on an x64 host but have not been run on native ARM64 Windows. JUCE omitted the optional VST3 `moduleinfo.json`; hosts can still load the module factory, although scanning may take longer.

**Website:** [MagDrum landing page](https://magdrum-library.cgi.chatgpt.site) (private, owner-only). Its source is [docs/index.html](docs/index.html). GitHub Pages is unavailable for this private repository on the current plan; the private Site hosts the landing page and its stylesheet separately from the application source.

## Phase 1 foundation

The Windows MagDrum VST3 has four editor views: a duration/brightness sample map, a DR-660-inspired 4×4 drum machine with waveform and velocity layers, a 16-bar sequencer with selectable time signatures and step velocities, and MIDI mapping profiles. It scans common Native Instruments, Spectrasonics/STEAM and Steinberg/Cubase audio folders directly from the plug-in, and shares the standalone library database. See [Windows VST3 workflow](docs/windows-plugin.md).

This repository contains a JUCE/CMake desktop app, background WAV/AIFF/FLAC scanning (subject to JUCE decoder support) with cancellation, a version-upgraded SQLite sample index, multi-window audio measurements, including spectral flatness, basic heuristic classification, category correction, user tags, similarity lookup, semantic drum-event and GM MIDI mapping, custom profile persistence/editing, and PPQ MIDI import/export. MIDI tempo and time signature can be edited at any beat without dropping other metadata. The editor reports ambiguous note assignments and compares the imported pattern with its current state, including events, tempo/meter and pattern length. The eight-lane step sequencer appends bars using the current meter when it fits the grid; right-click a step to set its velocity. It renders a tempo-aware preview from indexed drum samples and can loop it in the standalone app. The desktop app discovers installed plugins, lets the user load an instrument and choose a kit, then scans MIDI notes 0–127 at selected velocities, repeated takes and capture settings. Non-silent previews and metadata are stored in SQLite and appear in the sample browser; acoustic fingerprint changes between adjacent sampled velocities and repeated triggers are reported as heuristic candidates for listening review. The MagDrum VST3 loads user-selected audio samples from file or the shared SQLite index onto MIDI notes and saves sample paths with plugin state.

Sample-folder scans are recorded in history and use saved file size/modification time to skip unchanged files on later scans. Audio files are processed in a stable path order, and each completed file is committed to SQLite with a scan checkpoint. After cancellation or restart, scanning the same folder resumes after the last completed audio file; a file interrupted mid-analysis is safely retried. The Windows smoke test verifies the saved checkpoint and that the resumed pass starts at the next file.

The desktop app can export and merge a portable metadata JSON archive containing user tags, manual categories and mapping profiles. Import matches files by exact SHA-256 and size, keeps local file paths and audio private, merges tags additively, and reports category/profile conflicts without overwriting local values. The archive is plaintext and user-managed; this is manual transfer, not cloud synchronization. See [cross-device sync status](docs/library-sync.md).

The desktop and mobile browsers fetch matching sample rows from SQLite in pages of 250. The desktop browser filters by sample folder, scanned instrument, kit, category, measured duration, spectral-brightness bands, classification confidence and text/tags; it sorts by name, duration or brightness. A review filter shows uncorrected Unknown or below-75% heuristic classifications, and each row shows the confidence score or a manual marker. This threshold is a triage aid, not a calibrated probability. Plugin previews show their MIDI note, velocity and articulation in the shared list. It also shows the selected waveform and can compare two waveforms side by side. Exact duplicates can be listed by matching file hashes. A separate near-duplicate search compares normalized spectral fingerprints from four points in each sound, along with duration and audio features. Results are listening candidates, not proof that two recordings sound identical.

Select a captured plugin preview and choose **Open source kit** to reopen its instrument with the saved kit state, when the instrument is still installed. See [the plugin scanning guide](docs/plugin-scanning.md) for the manual kit capture workflow, VST3 preset loading and their current limits.

The classifier is an early heuristic. It combines filename evidence with measured features for conservative Kick, Tom, Snare, and hi-hat suggestions; Tom confidence is intentionally capped below the review threshold. It adds searchable filename-derived articulation tags for ghost notes, flams, rolls, brushes, rimshots, stick techniques, and cymbal articulations. Audio attack timing can also add tentative Flam and Roll candidate tags when conservative pulse count and spacing rules match; these are candidates rather than confirmed technique labels. Its review filter surfaces Unknown and low-confidence results, but confidence has not been calibrated. A local evaluator found audio-only accuracy from 2.5% to 25.0% across three small labeled sets; filename cues raise scores but can use class names embedded in filenames. The same evaluator measures the production similarity search: two CC0 drum-library subsets returned 55.6% and 89.8% folder-category agreement, but neither result is listener validation and the higher score came from related variants of one kit. See [classifier evaluation](docs/classifier-evaluation.md) for methods and limits. A synthetic eight-file similarity fixture covers four pure-tone families at two gains; all eight queries retrieve their labeled gain variant at the 0.85 threshold, with 100% precision and recall. MIDI round-trip tests also generate 24 patterns with 1,536 varied semantic events across custom note mappings, velocities, PPQ positions, tempos and time signatures. These controlled fixtures do not replace review against real drum libraries and third-party MIDI files. Plugin note scans run in a separate process to contain plugin crashes. Tests cover worker recovery after a crash and an end-to-end scan of the built MagDrum VST3 with saved sample state, including an audible note capture. Behavior and crash recovery with third-party instruments remain to be verified. An initial iOS/AUv3 source target is present, but it still needs a Mac/Xcode build, signing and device testing.

The iOS source target imports selected local audio files through JUCE's security-scoped URLs into the shared app-group container, then scans them into the shared SQLite library. Its browser uses database-side search/category filters and 250-sample pages, with preview playback and GM semantic MIDI import/export. The shared UI also builds as a Windows desktop preview; that does not verify iOS document-provider or AUv3 runtime behavior.

## Build

Requires CMake 3.22+, C++20 and Git. JUCE and SQLite are fetched at pinned versions by CMake.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build --output-on-failure
```

On Windows, `pwsh -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows.ps1` builds and tests the standalone app and VST3, then creates the Cubase ZIP under `latest-publish`. Add `-Architecture ARM64` to cross-compile for Windows ARM64 when its Visual Studio toolset is installed. `Build-Unix.sh` builds Linux x64 on Linux/WSL2 and macOS VST3/AU on a Mac. See [local platform builds](docs/local-builds.md) for requirements and limits, and [classifier evaluation](docs/classifier-evaluation.md) for an optional local labeled-corpus evaluator.

See [roadmap](docs/roadmap.md) and [architecture](docs/architecture.md). No sample libraries or audio content are included. Some supported platform or plugin formats may use additional SDK components with their own terms; see [licensing and notices](docs/licensing.md).

See the current [semantic MIDI model](docs/midi-mapping.md) for its behavior and known mapping limitations.

The latest Windows x64 and ARM64 packages are in the [v0.1.1-test.87 release](https://github.com/MagnarHarestad/MagDrum/releases/tag/v0.1.1-test.87). It adds default audio-library and drum-MIDI discovery, a DR-660-inspired pad order, raised graphite controls with cyan/magenta highlights, a variable-meter 16-bar VST sequencer, and source, kit and MIDI metadata on captured instrument samples. The v0.1.1-test.87 release also includes a cross-built ARM64 package; its PE architecture is ARM64, and the ARM64 test binaries compile but have not been run on native ARM64 Windows. These are unsigned test builds; iOS/AUv3 has not been packaged.
