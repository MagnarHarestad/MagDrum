# MagDrum

MagDrum is a cross-platform drum sound library and MIDI mapping workspace. Browse WAV sample libraries alongside sounds from drum instruments, audition them, and transfer drum patterns through semantic MIDI mappings.

**MagDrum** is the product name. Formats are platform targets: VST3 on Windows, macOS and Linux; AU on macOS; AUv3 on iOS/iPadOS where supported. Phase 1 began as a standalone app and does not require a DAW or commercial instruments. Public test release [v0.1.1-test.156](https://github.com/MagnarHarestad/MagDrum/releases/tag/v0.1.1-test.156) contains Windows x64, Windows ARM64, and Linux x64 packages. Windows x64 and Linux x64 Release CTest suites pass 2/2. Linux x64 also passes the repository's Ardour VST3 scanner test, and `ldd` found no unresolved package dependencies; interactive DAW sessions and physical Linux audio hardware still need testing. Windows ARM64 was cross-compiled and architecture-checked, but native runtime testing remains outstanding. The desktop and VST packages include opt-in metadata folder sync. It exchanges tags, manual categories, and MIDI maps only; it does not transfer audio, file paths, or plug-in state. Merge is transactional; cloud-provider upload completion still needs user confirmation. MIDI export defaults to exact articulation mappings; the VST sequencer offers a saved fallback option and reports every fallback or omitted event. JUCE omitted the optional Windows ARM64 VST3 `moduleinfo.json`; hosts can query the module factory, although scanning may take longer. macOS and iOS packages require Apple hardware and SDKs and are not available yet.

**Website:** [MagDrum landing page](https://magnarharestad.github.io/MagDrum-Website/). The public GitHub Pages site is maintained in the [MagDrum-Website repository](https://github.com/MagnarHarestad/MagDrum-Website); its page source is mirrored from [docs/index.html](docs/index.html).

## Phase 1 foundation

The Windows MagDrum VST3 has five editor views: a duration/brightness sample map, a DR-660-inspired 4×4 drum machine with waveform and velocity layers, a 1–16-bar sequencer with selectable time signatures, per-step velocity and MIDI import length detection, MIDI mapping profiles, and a plugin scanner workspace. It can scan Native Instruments' shared Public Documents content location plus common Native Instruments, Spectrasonics/STEAM and Steinberg/Cubase audio folders directly from the plug-in, and shares the standalone library database. See [Windows VST3 workflow](docs/windows-plugin.md).

The VST3 and standalone app offer English, German, French, Spanish, Swedish, Norwegian, Danish and Finnish from the top-right ☰ menu under **Language**. English is the first-run default. The choice is saved in the shared per-user MagDrum settings folder and updates the library, drum machine, sequencer and MIDI-map views immediately.

This repository contains a JUCE/CMake desktop app, background WAV/AIFF/FLAC scanning (subject to JUCE decoder support) with cancellation, a version-upgraded SQLite sample index, multi-window audio measurements, including spectral flatness, basic heuristic classification, category correction, user tags, similarity lookup, semantic drum-event and GM MIDI mapping, custom profile persistence/editing, and PPQ MIDI import/export. MIDI tempo and time signature can be edited at any beat without dropping other metadata. The editor reports ambiguous note assignments and compares the imported pattern with its current state, including events, tempo/meter and pattern length. The eight-lane step sequencer appends bars using the current meter when it fits the grid; right-click a step to set its velocity. It renders a tempo-aware preview from indexed drum samples and can loop it in the standalone app. The desktop app discovers installed plugins, lets the user load an instrument and choose a kit, then scans MIDI notes 0–127 at selected velocities, repeated takes and capture settings. Non-silent previews and metadata are stored in SQLite and appear in the sample browser; acoustic fingerprint changes between adjacent sampled velocities and repeated triggers are reported as heuristic candidates for listening review. The MagDrum VST3 loads user-selected audio samples from file or the shared SQLite index onto MIDI notes and saves sample paths with plugin state.

Sample-folder scans are recorded in history and use saved file size/modification time to skip unchanged files on later scans. Audio files are processed in a stable path order, and each completed file is committed to SQLite with a scan checkpoint. After cancellation or restart, scanning the same folder resumes after the last completed audio file; a file interrupted mid-analysis is safely retried. The Windows smoke test verifies the saved checkpoint and that the resumed pass starts at the next file.

The desktop app can export and merge a portable metadata JSON archive containing user tags, manual categories and mapping profiles. Import matches files by exact SHA-256 and size, keeps local file paths and audio private, merges tags additively, and reports category/profile conflicts without overwriting local values. The archive is plaintext and user-managed; this is manual transfer, not cloud synchronization. See [cross-device sync status](docs/library-sync.md).

The desktop and mobile browsers fetch matching sample rows from SQLite in pages of 250. SQLite FTS5 trigram search indexes sample names and paths, user/classification tags, source names and plugin/kit names; one- and two-character searches keep a compatibility fallback. A Windows smoke fixture searches 250,000 indexed samples and verifies SQLite uses its FTS virtual-table index. The desktop browser filters by sample folder, scanned instrument, kit, category, measured duration, spectral-brightness bands, classification confidence and text/tags; it sorts by name, duration or brightness. A review filter shows uncorrected Unknown or below-75% heuristic classifications, and each row shows the confidence score or a manual marker. This threshold is a triage aid, not a calibrated probability. Plugin previews show their MIDI note, velocity and articulation in the shared list. It also shows the selected waveform and can compare two waveforms side by side. Exact duplicates can be listed by matching file hashes. A separate near-duplicate search compares normalized spectral fingerprints from four points in each sound, along with duration and audio features. Results are listening candidates, not proof that two recordings sound identical.

Select a captured plugin preview and choose **Open source kit** to reopen its instrument with the saved kit state, when the instrument is still installed. See [the plugin scanning guide](docs/plugin-scanning.md) for the manual kit capture workflow, VST3 preset loading and their current limits.

The classifier is an early heuristic. It combines filename evidence with measured features for conservative Kick, Tom, Snare, and hi-hat suggestions; Tom confidence is intentionally capped below the review threshold. It adds searchable filename-derived articulation tags for ghost notes, flams, rolls, brushes, rimshots, stick techniques, and cymbal articulations. Audio attack timing can also add tentative Flam and Roll candidate tags when conservative pulse count and spacing rules match; these are candidates rather than confirmed technique labels. Its review filter surfaces Unknown and low-confidence results, but confidence has not been calibrated. The latest measured audio-only result is 22.3% accuracy / 0.212 macro F1 on a 121-file kit subset; the three-kit result remains 25.0% / 0.195, and neither set produced suggestions at the 0.75 review threshold. Filename cues raise scores but can use class names embedded in filenames. The same evaluator measures the production similarity search: two CC0 drum-library subsets returned 55.6% and 89.8% folder-category agreement, but neither result is listener validation and the higher score came from related variants of one kit. See [classifier evaluation](docs/classifier-evaluation.md) for methods and limits. A synthetic eight-file similarity fixture covers four pure-tone families at two gains; all eight queries retrieve their labeled gain variant at the 0.85 threshold, with 100% precision and recall. MIDI round-trip tests also generate 24 patterns with 1,536 varied semantic events across custom note mappings, velocities, PPQ positions, tempos and time signatures. These controlled fixtures do not replace review against real drum libraries and third-party MIDI files. Plugin note scans run in a separate process to contain plugin crashes. Tests cover worker recovery after a crash and an end-to-end scan of the built MagDrum VST3 with saved sample state, including an audible note capture. Behavior and crash recovery with third-party instruments remain to be verified. An initial iOS/AUv3 source target is present, but it still needs a Mac/Xcode build, signing and device testing.

The iOS source target imports selected local audio files through JUCE's security-scoped URLs into the shared app-group container, then scans them into the shared SQLite library. Its browser uses database-side search/category filters and 250-sample pages, with preview playback and GM semantic MIDI import/export. The Windows desktop preview now includes the eight-language hamburger menu and localized controls; that does not verify iOS document-provider or AUv3 runtime behavior.

## Build

Requires CMake 3.22+, C++20 and Git. JUCE and SQLite are fetched at pinned versions by CMake.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build --output-on-failure
```

On Windows, `pwsh -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows.ps1` builds and tests the standalone app and VST3, then creates the Cubase ZIP under `latest-publish`. Add `-Architecture ARM64` to cross-compile for Windows ARM64 when its Visual Studio toolset is installed. `Build-Unix.sh` builds Linux x64 on Linux/WSL2 and macOS VST3/AU on a Mac. See [local platform builds](docs/local-builds.md) for requirements and limits, and [classifier evaluation](docs/classifier-evaluation.md) for an optional local labeled-corpus evaluator.

See [roadmap](docs/roadmap.md) and [architecture](docs/architecture.md). No sample libraries or audio content are included. Some supported platform or plugin formats may use additional SDK components with their own terms; see [licensing and notices](docs/licensing.md).

See the current [semantic MIDI model](docs/midi-mapping.md) for its behavior and known mapping limitations.

For release packages, cross-platform status, platform-specific limits and Cubase installation guidance, see [installation](docs/installing.md), [local builds](docs/local-builds.md) and the [roadmap](docs/roadmap.md). Plugin discovery, preset/program import and note scanning are available in the VST; opening a third-party instrument's own editor still uses a separate MagDrum window. These are unsigned test builds; Windows ARM64 is cross-built and not runtime-tested here; iOS/AUv3 has not been packaged.
